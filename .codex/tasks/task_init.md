# Task: `init` (аналог `git-private init`)

## Контекст
Нужно реализовать команду и use-case `init` в новом проекте Git Safe.
Старый проект `git-private` используется только как эталон поведения (read-only reference).

## Цель
Создать первичную инициализацию хранилища приватных данных в git-репозитории.

## Ожидаемое поведение (черновик)
- Команда запускается внутри git-репозитория.
- Создает state-директорию (по умолчанию `.gitsafe`, либо из `GIT_SAFE_DIR`).
- Создает начальный файл списка путей (пустой).
- Обновляет `.gitignore` правилом для исключений `*.safe` (как в legacy-поведении).
- Если уже инициализировано, возвращает ошибку `already initialized`.

## TUI интерфейс

Нет. Инициализация происходит без интерактивного ввода. Для инициализации с интерактивным выбором
нужно запустить команду без флагов в неинициализированном хранилищем.

## Нефункциональные требования (черновик)
- Логика инициализации не зависит от CLI-фреймворка (Clean Architecture).
- Ошибки должны быть явными и тестируемыми.
- Операции с файловой системой и git инкапсулированы в adapters/ports.

## Поведенческая совместимость с legacy
Reference: `git-private/commands/init.go`, `git-private/utils/config.go`.
Нужно сохранить совместимые сценарии там, где это оправдано.
